# Hợp đồng backend cửa sổ

`window_manager/mod.rs` sở hữu model và interface dùng chung: `WindowId`, `OpenWindow`, `Capabilities`, `WindowError`, `WindowManager`. Command Tauri và `platform::get_platform_info` chọn backend qua cùng factory. Chỉ adapter X11 hiện được bật; có DISPLAY trong phiên Wayland không đủ để nhận là X11 native. Phiên X11 thiếu DISPLAY (kể cả chuỗi rỗng) trả `x11_display_missing`. Factory chỉ chọn adapter; probe runtime vẫn cần xprop và thuộc tính EWMH thật.

Interface gồm capabilities/list/activate/close/force_kill. X11 triển khai trong `window_manager/x11.rs`: parsing xprop, canonical XID, EWMH, Xlib request và xkill đều ở đây. Các helper trả chuỗi chỉ là chi tiết private bên trong adapter. Command chung trả lỗi có cấu trúc; platform chuyển lỗi sang chuỗi code/message để giữ định dạng reasons hiện tại. Popup watcher dùng khai báo X11 đã chuyển từ lib.rs về module X11; popup coordinator chưa phải adapter Wayland.

ID là `WindowId` bọc chuỗi opaque, serialize/deserialize transparent nên wire format UI vẫn là `id: "0x12"`, không đổi sang object. Phần chung không parse số hoặc WM_CLASS thành ID. X11 xuất lowercase hexadecimal không có zero padding. Input legacy decimal/unprefixed hex còn được parser X11 chấp nhận, nhưng mọi action phải xác minh ID hiện thuộc `_NET_CLIENT_LIST`, trong giới hạn XID 32 bit khác zero, không phải cửa sổ nội bộ/panel/desktop. Active indicator so giá trị XID, không so title. ID không phải danh tính bền vững qua vòng đời cửa sổ hoặc X server; adapter mới phải định nghĩa cách kiểm tra ID hiện hành của mình.

WindowError serialize `{code, message, context: {backend, operation, target?}}`. Mã native hiện có được giữ nguyên (xprop_unavailable, xprop_failed, window_target_invalid/missing/internal, window_action_unsupported, force_quit_*). Lỗi chưa có mã nhận `window_<operation>_failed`. Target là ID yêu cầu, không phải PID do client khai báo hoặc tên cửa sổ. UI adapter G1.9 thêm tên command và hiển thị code/message mà không mất context. Lỗi chọn backend dùng operation select; lỗi probe dùng capabilities; các thao tác còn lại dùng list/activate/close/force_kill.

Thêm adapter cần triển khai trait và thêm lựa chọn tại factory; không thay model IPC hoặc sửa parser X11 để diễn giải token của compositor khác. Adapter không hỗ trợ thao tác phải trả lỗi rõ ràng, không dùng danh sách rỗng hoặc true giả. Close gửi yêu cầu mềm; force_kill là hành động riêng có xác nhận ở UI. X11 force_kill kiểm tra target rồi để X server giải quyết chủ sở hữu resource, không kill PID từ `_NET_WM_PID`.

Kiểm thử hợp đồng gồm selection theo session/DISPLAY, serialization ID giữ wire format, cấu trúc lỗi và fixture xprop chạy tiến trình riêng: exit khác zero, binary thiếu, capability thiếu, root list hỏng/rỗng, action không hỗ trợ, ID sai/zero/quá 32 bit/token backend khác và ID đã biến mất. Các fixture gọi cả helper và trait object để kiểm tra adapter thật không làm mất ngữ cảnh. Hồi quy desktop dùng --window-list-smoke, --force-close-smoke, --popup-smoke và --platform-tool-missing trên hồ sơ riêng. Chưa có adapter Wayland được xác minh.
